1. PRODUCT DESCRIPTION
================================================================================

MorningBriefing.AI is a Chrome New Tab extension designed as an "Automated Fact-Based 
Life-Logging Service" that bridges the gap between digital schedules, daily activities, 
and AI-powered insights.

Core Value Proposition:
  - Automatizes the creation of daily journals by synthesizing:
    • Calendar events and to-do items (via integrated CalendarWidget)
    • Personal reflections (via Daily Question prompts)
    • Real-time macro context (Weather, Stock Market, News Trends)
  
  - Delivers objective, data-driven daily records that serve as a personal 
    knowledge archive with zero manual entry overhead.

Key Differentiators:
  1. Midnight Auto-Synthesis: At 00:00 daily, the system automatically compiles 
     checked items, responses, and macro data into a single structured entry.
  
  2. Factual-Only Journaling: All generated entries follow an objective, 
     minimalist tone—no sentiment analysis or emotional interpretation.
  
  3. Selective Data Inclusion: Only user-confirmed items (checked calendar 
     events/todos + answered daily questions) are included in the final record.
  
  4. Macro+Personal Hierarchy: Journal entries clearly separate market/weather/news 
     (external context) from personal records (activities/reflections).

User Experience:
  - Upon opening a new tab, users see a personalized dashboard with:
    • Current macro data (weather, stocks, trending topics)
    • Upcoming calendar events and integrated to-do list
    • Daily question prompt for reflection
  
  - At midnight, the system automates journal synthesis and presents a 
    preview modal for user review before final storage.

Target User:
  - **Primary**: Professionals & knowledge workers who want structured daily records 
    without manual journaling friction.
  - **Secondary**: Users interested in quantified-self insights derived from calendar, 
    tasks, and environmental data.
  - **Universal**: Anyone who starts their day by turning on their computer screen—seeking 
    an immediate, organized, and frictionless entry into their daily workflow.

3.1 DATA INTEGRATION & API MANAGEMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

REQ-DI-001: Google OAuth Authentication
  Requirement:
    - User authenticates via Google OAuth (consent screen: Calendar + Contacts scopes)
    - Session token stored in Supabase auth
    - provider_token (OAuth token) automatically persisted for API access
    - Token refresh handled on session change

  Acceptance Criteria:
    - First login triggers OnboardingModal
    - Session persists across browser restarts
    - OAuth token accessible for subsequent API calls
    - Logout clears session + provider token

REQ-DI-002: Google Calendar Event Retrieval
  Requirement:
    - Fetch today's and upcoming calendar events via Google Calendar API
    - Events ingested as "scheduled items" within CalendarWidget
    - Time zone-aware scheduling (user's local TZ)
    - Cache policy: 5-minute TTL with force-refresh on demand

  Acceptance Criteria:
    - Calendar events appear in CalendarWidget's schedule section
    - Events sortable by start time
    - Completed calendar events can be checked off
    - Failed API call falls back to mock data

REQ-DI-003: Real-Time Weather Data Integration
  Requirement:
    - Fetch weather data using Groq LLM (location-based estimation, no explicit coordinates)
    - Display current conditions, temperature, and brief forecast
    - Cache policy: 10-minute TTL
    - Support both metric (Celsius) and imperial (Fahrenheit) units

  Acceptance Criteria:
    - WeatherWidget renders weather icon + temperature
    - Forecast visible in AI briefing context
    - Weather data included in midnight journal synthesis
    - Graceful fallback if API unavailable

REQ-DI-004: Stock Market & Currency Data (Twelve Data)
  Requirement:
    - Fetch KOSPI, NASDAQ, S&P500 indices and USD/KRW exchange rate
    - Display current price, % change, trend indicator
    - Cache policy: 5-minute TTL
    - Error handling for rate limit (fallback to cached or mock)

  Acceptance Criteria:
    - StocksWidget displays 5+ data points with live % change
    - Color coding: Green (positive) / Red (negative)
    - Refresh button shows spinner during API call
    - Mock data visible if all APIs fail

REQ-DI-005: News Trends Aggregation (Tavily Search)
  Requirement:
    - Fetch trending news/topics via Tavily Search API
    - Extract top 3-5 trending terms + source counts
    - Cache policy: 20-minute TTL
    - Clean extracted tags (remove HTML, special chars)

  Acceptance Criteria:
    - TrendsWidget / NewsWidget displays trending topics
    - Each trend shows source count (e.g., "+12 articles")
    - Topics clickable to view related news detail modal
    - Trending data included in midnight journal [Macro Events] section

REQ-DI-006: API Caching & Fallback Strategy
  Requirement:
    - Implement multi-layer caching:
      • Supabase api_cache table (server-side, TTL per API)
      • localStorage (client-side, indexed by cache key)
    - Cache key format: `{dataType}_{timestamp}`
    - Stale cache detection: If current time > stored time + TTL, refetch
    - Fallback sequence: DB cache → Force API → localStorage → Mock

  Acceptance Criteria:
    - First load: API call → DB cache saved → localStorage saved
    - Second load (within TTL): DB cache used immediately
    - Subsequent visits (cache expired): API call triggered
    - Network failure: localStorage or mock data shown
    - Force-refresh button bypasses cache TTL check

REQ-DI-007: Edge Functions & API Orchestration
  Requirement:
    - Supabase Edge Functions deployed for:
      • /groq (weather text generation)
      • /stocks (Twelve Data fetch)
      • /tavily (news trend extraction)
      • /smart-widget (AI content generation)
      • /calendar (Google Calendar sync)
    - All secrets (API keys) stored in Supabase Secrets Manager
    - Error handling returns JSON with { error, message } on failure

  Acceptance Criteria:
    - All functions deployed and tested
    - Secrets not exposed in frontend.env
    - Function logs accessible for debugging
    - 30-second timeout with user-friendly error message

3.3 AUTOMATION & MIDNIGHT JOURNAL SYNTHESIS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

REQ-AJ-001: Midnight Auto-Synthesis Orchestration
  Requirement:
    - Single automated trigger at 00:00 that:
      1. Collects all checked todos from CalendarWidget (past 24h)
      2. Collects all completed calendar events (past 24h)
      3. Retrieves today's daily question response + memo
      4. Fetches macro data snapshot (weather, stocks, trends)
      5. Calls AI to generate multi-section journal entry
      6. Displays journal preview modal to user
      7. Saves finalized entry to Supabase on user confirmation
    - Process idempotent: Only one synthesis per calendar day

  Acceptance Criteria:
    - Trigger fires at 00:00 ±1 minute
    - All data collected in sequence (no race conditions)
    - Journal preview shown before persistence
    - If user closes modal without saving: Entry auto-saved after 30s
    - No duplicate entries even if trigger fires multiple times

REQ-AJ-002: Journal Data Collection Phase
  Requirement:
    - Format checked items as human-readable list:
      • "09:00 Team standup meeting"
      • "Complete project proposal"
      • "Lunch with client"
    - Include daily question response (if filled)
    - Include memo/notes (if filled)
    - Collect macro data snapshot:
      • Weather: Current condition, temp, forecast
      • Stocks: Market indices % change
      • News: Top 3-5 trending topics

  Acceptance Criteria:
    - Checked items formatted as: "HH:MM Title" (time if available)
    - Daily question response included verbatim
    - Memo preserved as-is
    - Macro data retrieved from cache or fresh API call
    - All data compiled into single context object for AI

REQ-AJ-003: AI Journal Generation (Groq LLM)
  Requirement:
    - Prompt Groq to generate multi-section journal entry:
      • Tone: Objective, factual, minimalist (no emotional inference)
      • Format: Structured text with clear section dividers
      • Sections:
          [Macro Events]
          - Weather summary (1-2 sentences)
          - Market update (stocks with % change)
          - News highlights (top 3 trending topics)
        
          [Personal Records]
          - Activities completed (formatted list of checked items)
          - Calendar events attended
          - Daily reflection (question response)
          - Notes/memo (if provided)
      • Length: ~300-500 words total

  Acceptance Criteria:
    - Generated entry separates [Macro Events] and [Personal Records]
    - Tone is factual (no "I felt", "it was amazing", etc.)
    - All checked items represented in entry
    - Daily question response included verbatim
    - Macro data contextualized (e.g., "Market down 1.2% due to..." avoided)
    - Response completes within 10 seconds

REQ-AJ-004: Journal Preview & Review Modal
  Requirement:
    - Modal displays generated journal entry immediately
    - User can:
      • Review before saving (read-only initially)
      • Edit text directly (optional fine-tuning)
      • Confirm to save → persists to Supabase
      • Discard → clears preview (entry not saved)
    - Save button triggers Supabase insertion

  Acceptance Criteria:
    - Preview modal appears exactly at 00:00 (or on next app open if closed)
    - Modal blocks dismissal for 10 seconds (ensure visibility)
    - Text editable in preview (optional user refinement)
    - Confirm button saves to diaries table with metadata
    - Discard option removes preview without saving
    - Auto-save fallback after 30s inactivity

REQ-AJ-005: Journal Data Storage
  Requirement:
    - Store final entry to Supabase diaries table:
      • Fields: user_id, date, generated_entry, macro_data, personal_data
      • Timestamp: created_at automatically set to 00:00 of that day
      • Status: "completed" or "draft" (if user edited, mark as "user_edited")
    - Entry retrievable via diary history (DiaryModal date picker)

  Acceptance Criteria:
    - Entry saved with correct user_id and date
    - Macro and personal sections stored separately (for future analytics)
    - Entry accessible via DiaryModal for same calendar day
    - Search/filter by date works correctly
    - One entry per calendar day enforced (overwrite on re-synthesis)

REQ-AJ-006: Objective AI Tone Enforcement
  Requirement:
    - AI Briefing + Journal Generation must NOT include:
      ✗ Emotional language ("I felt", "was wonderful", "disappointed")
      ✗ Comparative analysis ("unlike usual", "surprisingly", "fortunately")
      ✗ Predictive tone ("likely to", "probably will", "might happen")
    - Instead:
      ✓ Factual statements ("Weather: 23°C, Cloudy")
      ✓ Event descriptions ("3 meetings completed", "KOSPI +1.2%")
      ✓ Data summary ("News: 5 trending topics", "No calendar conflicts")

  Acceptance Criteria:
    - Prompt includes explicit instruction: "Generate only factual, objective content"
    - Human review of sample entries confirms no emotional language
    - Test prompts verify tone compliance
    - User feedback forum for tone violations

REQ-WS-001: Dashboard Layout Architecture (1:3:3 Frame)
  Requirement:
    - Implement a strict 1:3:3 width-ratio layout using Flexbox with three column zones:
      
      1. **Left Column (Ratio 1) - Pinned Sidebar**:
         • BriefingWidget: AI-generated brief with expandable modal + settings gear
         • DiaryCard: Daily Question prompt + user response input
         • Behavior: `flex-shrink: 0`, no internal scroll, fixed height relative to viewport
         • Min-width: 200px, Max-width: 280px (responsive constraint)
      
      2. **Middle Column (Ratio 3) - Widget Scroll Box**:
         • Container: Dedicated scrollable area ("Widget Box") for Standard Widgets
         • Widget Style: **1 widget per row** (100% width, horizontal wide-card format)
         • Scrolling: `overflow-y: scroll` with **always-visible scrollbar**
         • Scrollbar: Custom-styled, 8px width, theme-aware (light/dark)
         • Height: Flex-based, fills remaining viewport height after TopNav header
         • DnD: Vertical single-column drag-and-drop via @hello-pangea/dnd
         • Visual Feedback: Light blue background tint on drag-over
      
      3. **Right Column (Ratio 3) - Pinned Sidebar**:
         • CalendarWidget: Full-height calendar view with integrated todo section
         • Behavior: `flex-shrink: 0`, no internal scroll, fixed height relative to viewport
         • Min-width: 300px, Max-width: 500px (responsive constraint)
    
    - TopNav Header: Sticky positioning, contains clock, search, QuickLinks, theme toggle
    - Responsive: Maintains 1:3:3 ratio on desktop (1200px+); columns do not collapse
    - State Persistence: Widget order saved to `priorityOrder` in Supabase + localStorage
    - DnD Order = LLM Briefing Priority: Widget order in Middle Column defines AI briefing data priority

  Acceptance Criteria:
    - Left & Right columns remain pinned (no scroll) while Middle Column scrolls independently
    - Middle Column scrollbar is always visible (not auto-hide)
    - TopNav header stays fixed above the three-column layout
    - Standard widgets stack vertically (1 per row, full-width horizontal cards)
    - Drag-and-drop reorders widgets within Middle Column only
    - Widget order persists across page refresh and login sessions
    - Reordering widgets updates LLM briefing priority in real-time
    - 1:3:3 ratio preserved at all supported viewport widths (≥1200px)

        |-----------------|----------------|-----------|--------------------------------|
