MorningBrief.AI Data Design Presentation Script (Approx. 4-5 Mins)

1. Introduction (30s)

"Hello everyone, we are Team 3pip, and today we’ll present the data design for MorningBrief.AI, our AI-powered personalized dashboard. Our goal was to create a system that seamlessly blends static user data with dynamic real-time information to provide a tailored 'morning start' experience."

2. Core Architecture: Supabase & API Strategy (1m)

"For our implementation, we chose Supabase, which provides a robust PostgreSQL environment.
One of the biggest challenges in a dashboard app is managing multiple external APIs—like Weather, Stocks, and News. To handle this efficiently, we designed a centralized ApiCache system.
Instead of hitting external APIs every time a user refreshes the page, we store the results in an ApiCache table with a unique cache_key. This significantly reduces latency and ensures we stay within API rate limits."

3. Persistent Data Model (1m)

"Looking at our UML, we have the core User entity connected to UserSettings and WidgetLayouts in a 1-to-1 relationship.

UserSettings stores the user's 'Persona' and 'Tone'—which the AI uses to customize the briefing style.

WidgetLayouts uses a JSONB format to remember exactly where each user placed their widgets.

We also have Todo and Diary entities. A key feature here is the is_fixed flag in the Todo model, which allows certain routines to persist while others are cleared daily."

4. The 'Briefing' Logic: Aggregation (1m)

"The heart of our app is the BriefingWidget. As you can see in the UML, this isn't just a simple table; it's an Aggregation Point.
At runtime, the system gathers data from all other entities—Weather, Health, Calendar, and Tasks—and feeds this 'Context Object' into the Groq LLM.
This is how we transform raw database rows into a natural, friendly greeting like: 'Good morning Minsoo! It's raining outside, so don't forget your umbrella before heading to your 10 AM class.'"

5. Front-end Integration & Conclusion (30s)

"Our front-end is built with React, where each class in our UML maps directly to a UI component. This modularity allows us to use the vis settings in the database to show or hide widgets dynamically.
In summary, our data design prioritizes performance through caching and personalization through structured AI context. Thank you!"
