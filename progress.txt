BUG #2: Strict PIN Session / State Reset (FIXED)
================================================================================

ISSUE:
  Once a PIN was entered and verified, the diary would stay unlocked forever
  (or until page refresh). This is a security bug - the diary should lock
  again when the user:
  - Closes the date details view
  - Selects a different date
  - Clicks a lock button

SECURITY CONCERN:
  Private diary data should not persist unlocked across multiple date views.
  If user walks away from computer, subsequent dates should not auto-unlock.

SOLUTION IMPLEMENTED:
  [✓] Added clearPinSession() method to useDiaryStore (without resetting PIN)
  [✓] DiaryPanel now resets authentication on component unmount:
      - useEffect cleanup resets isAuthenticated on date change
      - User must re-enter PIN for every new date
  [✓] Added Lock button (header) to manually lock diary:
      - Calls clearPinSession() to reset auth
      - Closes date panel with onClose()
  [✓] Session auth resets during date switching:
      - useEffect dependency on selectedDate
      - Cleanup function calls clearPinSession()

NEW STORE METHOD:
  clearPinSession: () => {
    save(PIN_AUTH_SESSION_KEY, false);
    set({ isPinAuthenticated: false });
  }
  
  Note: This is different from resetPIN() which also forgets the PIN itself.
  clearPinSession() only resets the session flag - PIN remains stored.

CODE FLOW:
  1. User enters PIN → verifyPIN() sets isPinAuthenticated: true
  2. Diary unlocks, content visible
  3. User selects different date → useEffect cleanup triggers
  4. clearPinSession() called → isPinAuthenticated: false
  5. Diary locks again for new date
  6. User must re-enter PIN

USER EXPERIENCE:
  - Strict security: diary locks when switching dates
  - User control: lock button available when diary is open
  - Privacy: no accidental exposure if user walks away
