Personalization Logic (for Smart Widget / People Widget)
Last Updated: 2026-04-21

==================================================
1) 목적
==================================================
사용자의 Q&A 응답에서 관심 키워드를 추출하고, 최근성 가중치 기반 점수로 누적해
스마트 위젯/사람들 위젯의 검색 및 추천 개인화에 사용한다.


==================================================
2) 키워드 추출 규칙 (AI API)
==================================================
입력: "오늘 수집된 Q&A 목록"
예시 입력:
[
  { "question": "오늘 먹고 싶은 음식이 있어?", "answer": "짜장면" },
  { "question": "요즘 즐기는 취미가 있어?", "answer": "헬스 요즘 시작했어" }
]

출력 규칙:
- 결과는 "JSON 배열"만 반환
- 설명/마크다운 금지
- 각 답변에서 여러 키워드 추출 가능
- 카테고리 고정값:
  food, place, content, shopping, lifestyle, mood, interest
- 키워드는 검색 가능한 구체 명사 형태로 정규화
  예) "헬스 시작했어" -> "헬스"

예시 출력:
[
  { "keyword": "짜장면", "category": "food" },
  { "keyword": "중식", "category": "food" },
  { "keyword": "면류", "category": "food" },
  { "keyword": "헬스", "category": "lifestyle" },
  { "keyword": "운동", "category": "lifestyle" }
]


==================================================
3) 일일 처리 플로우
==================================================
[하루 동안]
질문 위젯 -> 사용자 답변 -> raw Q&A DB 저장

[자정 배치]
raw Q&A(당일분) -> AI API(위 규칙) -> 키워드 추출
추출된 각 키워드에 대해 score_log에 row INSERT:
(keyword, category, date)


==================================================
4) 점수 계산 로직 (위젯 호출 시)
==================================================
각 키워드의 최종 점수:
score = SUM((30 - elapsed_days) / 30),  단 elapsed_days < 30

정의:
- elapsed_days = (오늘 날짜 - row.date)
- elapsed_days가 작을수록 가중치가 큼
- 30일이 지난 데이터는 점수 계산에서 제외

동작:
1. score_log에서 elapsed_days < 30인 row만 조회
2. keyword(+category) 기준으로 가중치 합산
3. score 내림차순 정렬
4. 상위 키워드 반환 -> 검색/추천 커스터마이징에 사용


==================================================
5) 자동 정리 (데이터 만료)
==================================================
배치 작업으로 elapsed_days >= 30인 score_log row 삭제

효과:
- 오래된 관심사는 자연스럽게 감쇠/삭제
- 최근 취향이 추천에 더 강하게 반영됨


==================================================
6) 구현 시 체크포인트
==================================================
- AI 응답이 JSON 배열이 아니면 재시도 또는 실패 처리
- category가 고정값 목록에 없으면 필터링
- 빈 문자열 keyword 제거
- keyword/category 공백 trim 및 명사 형태 정규화
- 배치 실패 시 재처리 가능하도록 처리일(date) 기준 idempotent 설계 권장
