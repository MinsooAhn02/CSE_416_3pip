1. 프로젝트 개요
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

프로젝트명: MorningBrief.AI
형태: Chrome New Tab Extension (React 기반 대시보드)
목표: 사용자 데이터(날씨, 주식, 뉴스, 일정, 건강 정보)를 한눈에 파악하고,
      AI 기반 브리핑 및 일기/TODO 관리 기능 제공

핵심 기술 스택:
  - Frontend: React 18 + Vite
  - 상태 관리: Zustand
  - UI: Tailwind CSS 3 + Lucide React 아이콘
  - 드래그: @hello-pangea/dnd (DND library)
  - 백엔드: Supabase (Auth, DB, Edge Functions)
  - LLM: Groq API
  - 데이터: Twelve Data, Tavily Search, Kakao Local, Google APIs

3-1) 인증 & 온보딩 (useAuthStore)
─────────────────────────────────────────────────────────────────────────────

기능:
  - Google OAuth 로그인 (calendar, fitness scope 포함)
  - 세션 관리 (Supabase)
  - provider_token 자동 저장
  - 신규 유저 온보딩 분기 (OnboardingModal 자동 표시)

주요 함수:
  - login(): Google OAuth 시작
  - handleAuthChange(session): 세션 변경 처리
  - loadUserSettings(): DB에서 설정 로드
  - ensureProviderToken(): 토큰 재확보

사용처:
  - App.jsx: isLoggedIn 체크 → LoginScreen 또는 대시보드 표시
  - 데이터 로드: provider_token으로 Google 데이터 접근


3-2) 설정 & 테마 (useSettingsStore, useTheme)
─────────────────────────────────────────────────────────────────────────────

지원 설정:
  - 테마: "dark" (회색계) / "light" (밝은 배경)
  - 시계 스타일: "digital" / "analog"
  - 브리핑 톤: "formal" / "casual"
  - 브리핑 길이: "short" (1줄) / "medium" (3줄) / "long" (5줄)
  - 음성 ON/OFF
  - 인격(persona): 미리 설정된 프로필

다크/라이트 모드:
  - Tailwind dark: 클래스 조건부 렌더링
  - useTheme(): isDark, cardCls, muted, inputCls 반환
  - transition-colors duration-300: 부드러운 전환

시계 스타일:
  - Digital: 현재 시각 대형 표시 (TopNav 중앙)
  - Analog: 아날로그 시계 컴포넌트 (AnalogClock.jsx)


3-3) 데이터 로딩 (useDataStore)
─────────────────────────────────────────────────────────────────────────────

Selective Loading:
  - 모든 위젯 데이터를 한번에 로드하지 않음
  - 활성 위젯만 선별 로드 (activeWidgetIds 기준)
  - 사용자가 위젯 visibility 설정 → 동적 로드

캐시 전략 (TTL):
  - weather: 10분
  - stocks: 5분
  - trends: 20분
  - restaurants: 20분
  - calendar: 5분
  - health: 15분

각 fetch 함수 구조:
  1) DB api_cache 조회 (key, TTL 검사)
  2) 캐시 유효 → 즉시 반환
  3) 캐시 만료 또는 force=true → Edge Function 호출
  4) 성공 → normalize + DB 저장 + localStorage 저장
  5) 실패 → mock 데이터 fallback

API 별 상세:
  - 날씨: Groq LLM (좌표 기반 현실적 추정)
  - 주식: Twelve Data (KOSPI, NASDAQ, S&P500, USD/KRW)
  - 트렌드: Tavily Search (실시간 검색 + 요약)
  - 맛집: Kakao Local API (좌표 기반, radius 1200m)
  - 캘린더: Google Calendar (OAuth token 필요)
  - 건강: Google Fit (provider_token 필요)

3-8) 스마트 위젯 (SmartWidgetContent + smart-widget Edge)
─────────────────────────────────────────────────────────────────────────────

동작 원리:
  1) 사용자 AddSmartWidget에서 키워드 입력 (예: "AI 뉴스")
  2) useWidgetStore.smartKeywords에 저장
  3) SmartWidgetContent 마운트 → loadSmartWidget() 호출
  4) Edge function smart-widget 호출
     - Route 결정: weather/stocks/trends/restaurants/etc.
     - persona 기반 검색 포인트 3개 생성
     - Tavily 검색 → Groq 요약
  5) 결과 렌더 (emoji, sections, lastUpdated, debug)

캐싱:
  - smartWidgetData[keyword]: 생성된 데이터
  - smartWidgetErrors[keyword]: 에러 메시지
  - useEffect with force 파라미터: 강제 재생성

[1] 다크/라이트 모드 전환

  → 색상 부드럽게 변경 (0.3초)

[2] 시계 스타일 변경
  → 오른쪽 상단 설정(⚙️) 클릭
  → "시계 스타일" 탭
  → "디지털" 또는 "아날로그" 선택
  → TopNav에 즉시 반영

[3] 즐겨찾기 웹사이트 관리
  → 오른쪽 상단 원형 아이콘 (즐겨찾기)
  → 마우스 오버 → 6개 웹사이트 링크 펼쳐짐
  → 점 3개(⋮) → 편집 모달
    - 웹사이트 추가/삭제
    - 이름, URL, 아이콘 설정
  → 링크 클릭 → 새 탭에서 해당 사이트로 이동

[4] 위젯 드래그 (위치 변경)
  → 위젯 드래그 핸들 (🔲 아이콘) 잡기
  → 다른 위치로 드래그
  → 드롭 존(col1/col2/col3/calendar)에 놓기
  → 자동 저장 (localStorage + DB)
  → 다음 접속 시 같은 위치 유지

[5] 브리핑 새로고침
  → BriefingWidget의 새로고침(🔄) 버튼
  → AI 브리핑 재생성
  → 15초 정도 소요 (Groq 호출)

[6] 날씨, 주식, 뉴스 각 위젯의 새로고침
  → 각 위젯 상단 새로고침(🔄) 버튼
  → 강제 API 재호출 (캐시 무시)

[7] 일기 쓰기
  → 중앙 DiaryCard
  → "오늘 가장 기분 좋았던 순간은 언제인가요?" 질문 아래
  → textarea에 답변 입력
  → "확인" 버튼 클릭
  → 저장된 항목 리스트 아래 표시
  → 내용 많으면 스크롤 가능

[8] 날짜별 일기 조회/편집
  → 오른쪽 캘린더에서 날짜 클릭
  → DiaryModal 열기
  → 그날 일기 내용 + 메모 표시
  → 메모 편집 후 저장

[9] TODO 관리
  → TodoWidget
  → "추가" 버튼으로 새 TODO 생성
  → 체크박스로 완료 표시
  → "루틴" 배지: 고정 TODO (매일 자동 리셋)

[10] 고정 TODO (루틴) 추가
  → 설정(⚙️) → "고정 TODO" 탭
  → "루틴 추가" 버튼
  → 루틴명 입력, 시간 설정 (선택)
  → 저장
  → 매일 자동으로 재등장

[11] 스마트 위젯 생성
  → 설정(⚙️) → "스마트 위젯" 탭
  → "새 키워드 추가"
  → 키워드 입력 (예: "AI 뉴스", "주식 분석", "맛집 추천")
  → 저장
  → SmartWidget 자동 생성 (20초 정도, Tavily + Groq)

[12] 검색
  → TopNav 중앙 검색 바
  → 검색어 입력
  → Enter 또는 검색 아이콘 클릭
  → Google 검색 결과 새 탭에서 열기

5-3) API 테스트 (PowerShell)
─────────────────────────────────────────────────────────────────────────────

# 환경변수 로드
$envMap = @{}
Get-Content .env |
  Where-Object { $_ -match '^[A-Za-z_][A-Za-z0-9_]*=' } |
  ForEach-Object { $k,$v = $_.Split('=',2); $envMap[$k]=$v }

$base = "$($envMap.VITE_SUPABASE_URL)/functions/v1"
$key = $envMap.VITE_SUPABASE_ANON_KEY
$headers = @{ apikey=$key; Authorization="Bearer $key"; 'Content-Type'='application/json' }

# Groq 테스트 (날씨)
Invoke-RestMethod -Method Post -Uri "$base/groq" -Headers $headers `
  -Body '{"system":"날씨 JSON 생성기","prompt":"좌표 37.5665,126.978 기반 현실적 날씨 JSON","temperature":0.2}'

# Stocks 테스트
Invoke-RestMethod -Method Post -Uri "$base/stocks" -Headers $headers `
  -Body '{"symbols":["KOSPI","NASDAQ","SP500","USDKRW"]}'

# Tavily 테스트
Invoke-RestMethod -Method Post -Uri "$base/tavily" -Headers $headers `
  -Body '{"query":"대한민국 실시간 이슈 트렌드"}'

6. 문제 해결 & 유지보수
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

6-1) 일반적인 문제
─────────────────────────────────────────────────────────────────────────────

[문제] 로그인 후 대시보드가 안 보임
→ 원인: isLoggedIn이 false, 또는 세션 로드 지연
→ 해결:
  1) Chrome DevTools 콘솔 확인
  2) useAuthStore 상태 로그 출력
  3) Supabase 연결 확인 (.env 파일)
  4) 로컬 저장소 초기화: localStorage.clear() → 새로고침

[문제] 위젯 데이터가 0 또는 나타나지 않음
→ 원인: API 호출 실패, 캐시 오염, 또는 mock fallback 사용 중
→ 해결:
  1) DevTools Network 탭에서 Edge Function 호출 확인
  2) 응답 상태 코드 (200 vs 4xx/5xx)
  3) 캐시 초기화: localStorage.clear()
  4) API 키 확인 (Supabase Secrets)
  5) 함수 재배포: npx supabase functions deploy

[문제] 드래그 후 위치가 저장되지 않음
→ 원인: localStorage 비활성화, 또는 Supabase DB 저장 실패
→ 해결:
  1) localStorage 활성화 확인
  2) 브라우저 개발자도구 → Application → localStorage 확인
  3) Supabase 권한(RLS) 확인
  4) widget_layouts 테이블 존재 확인

[문제] 자정 일기가 자동 생성되지 않음
→ 원인: 브라우저 닫혀 있음, 또는 setInterval 미실행
→ 해결:
  1) 브라우저 계속 열어두기
  2) 다음 접속 시 자동 생성 로직 (checkAndGenerateMissingDiary)
  3) App.jsx useEffect 확인


6-2) API/데이터 문제
─────────────────────────────────────────────────────────────────────────────

[문제] 날씨만 안 나타남
→ 원인: GROQ_API_KEY 누락 또는 groq 응답 JSON 파싱 실패
→ 해결:
  1) Supabase Secrets 확인: npx supabase secrets list
  2) Groq API 키 재설정: npx supabase secrets set GROQ_API_KEY=xxx
  3) 함수 재배포: npx supabase functions deploy groq

[문제] 주식 가격이 전부 0
→ 원인: Twelve Data 한도 초과, 또는 심볼 오류
→ 해결:
  1) Twelve Data 계정 확인 (할당량)
  2) API 키 재발급
  3) supabase/functions/stocks/index.ts의 심볼 확인
  4) 함수 재배포

[문제] 트렌드가 이상한 태그로 나타남
→ 원인: Tavily 응답 정제 규칙 미흡
→ 해결:
  1) Tavily API 키 유효한지 확인
  2) supabase/functions/tavily/index.ts의 정제 로직 검토
  3) 응답 형식 확인 (trends 배열 구조)

[문제] 캘린더 이벤트가 보이지 않음
→ 원인: Google OAuth token 만료, 또는 권한 부족
→ 해결:
  1) 다시 로그인 (Google 권한 재동의)
  2) useAuthStore.ensureProviderToken() 호출 확인
  3) calendar scope 포함 확인
  4) Google Calendar 공개 권한 확인

6-4) 보안 주의사항
─────────────────────────────────────────────────────────────────────────────

API 키 관리:
  - 클라이언트에 API 키 노출 금지 (VITE_* 변수는 최소화)
  - 모든 API 호출은 Edge Function 프록시 사용
  - Supabase Secrets에 저장 (환경변수)

Supabase RLS (Row Level Security):
  - user_id 기반 접근 제어 필수
  - api_cache, todos, diaries 테이블 RLS 활성화
  - 정책 검토: INSERT/SELECT/UPDATE/DELETE 권한 확인

Supabase 권한:
  - anon key: 클라이언트용 (로그인 전)
  - service_role key: 서버용 (절대 클라이언트 노출 금지)
